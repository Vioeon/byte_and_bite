## 📌 문제 발생

### 1. 문제 유형 (핵심 태그) 정의

- UI/UX 버그

### 2. 어떤 기능에서 문제가 발생했는가?

- 댓글 페이지네이션을 구현한 후 확인해보니, 뉴스 목록 및 맛집 리뷰 목록 페이지와 비교했을 때 댓글 페이지네이션의 글꼴이 다르게 표시되는 문제가 발생하였다.

- 페이지네이션의 기능(페이지 이동, 이전/다음 버튼)은 정상적으로 동작했지만, 댓글 상세 페이지에서만 글꼴이 달라 보여 전체 프로젝트의 UI 일관성이 깨지는 문제가 있었다.

- 같은 프로젝트 내 페이지네이션임에도 화면마다 디자인이 달라 보여 사용자 경험(UI/UX)이 일관되지 않았다.

---

## 🔍 원인 분석

### 왜 발생했는가?

### 어떤 코드/구조에서 문제가 있었는가?

- 댓글 상세 페이지는 `postDetail.css`를 사용하고 있었고, 리뷰 목록 페이지는 `postList.css`를 사용하고 있었다.

- `postDetail.css`의 `.detail-wrapper`에 `font-family`가 별도로 지정되어 있어 공통 스타일보다 우선 적용되면서, 댓글 페이지네이션의 글꼴이 리뷰 목록 페이지와 다르게 표시되었다.

- 즉, 페이지네이션의 CSS 자체에는 문제가 없었지만, 상세 페이지에서 별도로 지정한 `font-family`가 적용되어 동일한 UI임에도 글꼴이 달라지는 문제가 발생하였다.

---

## 🛠 해결 방법

### 어떻게 해결했는가?

- `postDetail.css`에 별도로 지정된 `font-family`를 제거하여 공통 CSS의 글꼴을 사용하도록 수정함으로써, 댓글 페이지네이션과 리뷰 목록 페이지의 UI를 동일하게 맞추었다.

---

## 🧠 배운점

### 트러블 슈팅을 통해 깨달은 부분

- UI 문제는 기능이 정상적으로 동작하더라도 CSS의 우선순위나 공통 스타일 적용 여부에 따라 화면이 다르게 표시될 수 있다는 점을 알게 되었다. 처음에는 페이지네이션 코드 자체의 문제라고 생각했지만, 실제 원인은 `font-family`가 별도로 지정된 CSS에 있었다.

- 이번 경험을 통해 문제를 해결할 때는 기능 코드뿐만 아니라 공통 CSS와 페이지별 CSS를 함께 비교하며 원인을 분석하는 과정이 중요하다는 것을 배웠다.
