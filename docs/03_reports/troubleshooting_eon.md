## 📌 문제 발생

### 1. 문제 유형 (핵심 태그) 정의

- 브라우저 캐시(BFCache)로 인한 조회수 갱신 오류

### 2. 어떤 기능에서 문제가 발생했는가?

- 상세 페이지에서 조회수가 증가한 후 브라우저의 '뒤로가기' 버튼을 눌러 목록 화면으로 돌아왔을 때, **최신 조회수가 반영되지 않고 이전 상태의 화면이 그대로 표시**되는 현상 발생.

---

## 🔍 원인 분석

### 왜 발생했는가?

- 브라우저의 **BFCache(Back/Forward Cache)** 기능으로 인해 발생

### 어떤 코드/구조에서 문제가 있었는가?

- 서버 사이드 렌더링(SSR) 환경에서 클라이언트가 뒤로가기로 진입했을 때 서버에 최신 데이터를 재요청하지 않고 기존 DOM 상태를 그대로 유지함

- 뒤로가기 시점에 브라우저가 캐시에서 복원했는지(`persisted`) 여부를 확인하고 화면을 새로 갱신하는 별도의 이벤트 핸들러(`pageshow` 등)가 구현되어 있지 않음.

---

## 🛠 해결 방법

### 어떻게 해결했는가?

- `window.onpageshow` 또는 `window.addEventListener('pageshow')` 이벤트를 사용하여 페이지가 브라우저 캐시에서 복원되었는지 확인 (`persisted` 속성 이용).

- BFCache로부터 페이지가 로드된 경우 강제로 새로고침(`window.location.reload()`)을 수행하여 서버로부터 최신 데이터를 다시 불러오도록 수정.

---

## 🧠 배운점

### 트러블 슈팅을 통해 깨달은 부분

- **브라우저 캐싱 메커니즘 이해:** 단순히 서버 사이드 로직이나 DB 갱신에만 신경 쓸 것이 아니라, 브라우저가 제공하는 캐싱 최적화 기능(BFCache)이 사용자 경험에 미치는 영향을 이해하게 됨.
